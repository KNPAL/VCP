# Live pattern lifecycle

Migration 31 records immutable per-pattern, per-session observations and transitions in the daily detector transaction. Each observation pins the complete detector evidence, exact decimal pivot/leg values, configuration hash, adjustment/data revisions and source/decision times. WATCH_DATA maps to BLOCKED_DATA; it never becomes a verified WATCH or READY state.

The first observation transitions from DISCOVERED to the state actually observed. It does not manufacture intermediate historic states. Later unchanged states record an observation without another transition or alert. Changes record the prior observation and append one alert outbox identity atomically. DEVELOPING, WATCH, READY, BLOCKED_DATA, REJECTED, INVALIDATED and EXPIRED are supported. EXPIRED cannot revive; INVALIDATED can only remain invalidated or expire. Breakout price-only/confirmed events remain separate immutable market events linked by pattern identity and are included in the audit endpoint.

Same-session changed evidence is rejected instead of overwriting the first live observation. Older observations cannot be inserted behind later live history. Historical corrections use the separate correction-replay pipeline and preserve original live events. Missing listings do not imply a transition to READY or EXPIRED; full-scan missing coverage remains explicit in scan evidence. The original detector decides pattern validity independently of portfolio BUY permission.

`GET /api/v1/vcp/lifecycle/{patternId}` requires authentication and a SHA-256 pattern identity. It returns chronological observations/transitions and separate breakout records, or explicit UNKNOWN if no live observations exist. No mutation endpoint accepts client-supplied market states. The first observation after deployment may start a new audit history; migration does not fabricate prior events.

Verification: `node scripts/database-command.mjs test lifecycle database eod-scan` covers duplicate concurrent observations, unchanged-state suppression, exact six-decimal pivot retention, UNKNOWN/blocked state, correction immutability, terminal-state rejection, out-of-order history, immutable outbox identities, authentication and actual daily/EOD transaction integration. Unit scan tests separately verify stable ordering and partial coverage. Use `node --test tests/lifecycle.test.mjs` for state normalization.
