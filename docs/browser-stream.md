# Authenticated browser events (KAN-108)

Socket.IO namespace `/stream` uses WebSocket transport at `/api/v1/socket.io`. The handshake requires the existing owner session cookie, exact configured application origin and CSRF token. Handshake auth accepts only `csrfToken`, `listings` (up to 100 distinct canonical listing UUIDs), and an optional replay `cursor`. Owner identity is always read from the session. Session validity and current listing permissions are rechecked every poll; logout or revocation disconnects the socket. Ten concurrent connections per owner are allowed. Changing subscriptions requires a new handshake and a cursor for that subscription scope.

Migration 44 adds an immutable `StreamTimeline`. A serialized materializer projects references to existing immutable journal, stop, exit, monitor, alert, pattern, scan and decision evidence. Lost notifications can be rebuilt from those source records. Sequence allocation and commit are serialized so a consumer cannot advance past an uncommitted lower sequence. Original source evidence is preserved; materialization does not place orders or create fills. Historical evidence is imported in bounded batches. `eventAt` is the projection observation time; `sourceAt` is the source record's timestamp, or null when the source lacks one. `revision` and `correlationId` remain stable across replay.

`GET /api/v1/stream/events?listings=<comma-separated-UUIDs>&cursor=<opaque-cursor>&limit=100` returns `items`, `cursor`, `hasMore` and `asOf`. Limits are 1–200. Omit the cursor for initial history. Continue while `hasMore`; keep the returned cursor even for an empty page. Cursors are bound to the authenticated owner and exact sorted listing scope. Private position/decision/alert records are filtered by owner. Listing events require a permitted requested listing; completed scan references are available to the authenticated owner. References identify the source table and record; they do not expose another owner's evidence.

Durable event types are `pattern.changed`, `scan.completed`, `signal.created`, `decision.updated`, `position.changed`, `stop.changed`, `alert.created` and monitor `data.stale`. Every envelope includes `id`, decimal-string `sequence`, `eventAt`, nullable `sourceAt`, `revision`, `correlationId`, nullable `listingId`, a source reference, and `executable:false`. Socket delivery adds `durable:true`. Clients deduplicate by ID; delivery is at least once. `stream.cursor` supplies the replay cursor after a delivered batch.

`quote.updated` and transient `data.stale` are read from Redis and never added to the persistent timeline. Their `sequence` is null; the original provider sequence is in `quote.sequence`. A current quote must pass the same atomic lease/heartbeat/TTL read as protective monitoring, plus current calendar, token mapping and source-time validation. Expired prices become `data.stale` with a null quote. Clients must also stop treating a price as current at `validUntil`, even if the network stops delivering events. Socket availability never implies market-data availability.

For initial display, `tail=1` with no cursor returns at most the latest requested number of events in ascending order and a cursor at the current high-water mark. Older history remains available by omitting tail. Tail cannot be combined with a cursor. The workspace uses this bounded initial load, then connects from that cursor. On reconnect it reloads all missed events forward from its saved cursor. It deduplicates replay, shows paused/syncing/connected states and exposes the five most recent events. An actual journal change reloads holding subscriptions. It dispatches validated events as the browser `vcp:stream-event` custom event; existing position views retain their own evidence-expiry checks.

## Run and verify

Apply migration 44 before starting the rebuilt API. Use the documented web start command: `scripts/web-server.mjs` explicitly proxies only the Socket.IO WebSocket upgrade path to `API_INTERNAL_URL`, preserving origin and session headers. Ordinary HTTP still uses Next's request handler and rewrites. Local-server, the package start command, Docker and the test runner use this launcher. Do not substitute bare `next start` for local streaming. Caddy's `/api/*` reverse proxy forwards upgrades directly to the API in Docker. Set `APP_ORIGIN` to the exact public origin. For live quote fanout, give the API the same `VCP_STREAM_ACCOUNT_KEY` as the worker and Redis host/port; the API does not receive broker credentials. Docker overrides should set API `REDIS_HOST=redis`. Without a stream account, durable events still work and live quotes remain explicitly unavailable.

`node scripts/database-command.mjs test stream` tests rejected anonymous/wrong-origin/wrong-CSRF/invalid-listing handshakes, owner-bound cursors, immutable replay, reconnect, revocation, quote deduplication and expiry using only `vcp_test` and unique Redis keys. Browser verification is included by `VCP_BROWSER_TESTS=true` with the documented isolated web runner and web port 3002. No live provider connection is claimed by these synthetic tests.
