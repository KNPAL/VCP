# Portfolio reconciliation (KAN-95)

Migration 33 stores immutable, owner-scoped broker-statement comparisons. In **My positions → Reconcile outside activity**, enter independent statement cash, every holding (ISIN followed by integer shares, one per line), and all executed fill references since initial capital. Include outside trades and cash activity. An empty holdings list means the statement has no holdings. Confirm the source and its UTC as-of time; use current timestamp only for an account record actually checked now.

The comparison uses exact six-decimal cash, quantities across the union of statement and journal companies, and effective fill references after reversals/corrections. Missing initial capital, unconfirmed outside activity, cash/holding/reference mismatches or statements predating journal activity yield PORTFOLIO_UNRECONCILED with separate reasons. Fix the journal using actual fills, corrections and verified cash movements, then record a new independent statement. A statement never creates fills or changes cash.

A match is RECONCILED_AS_OF, bound to the complete journal hash and statement timestamp. Every journal append invalidates that match. This describes evidence at the statement's timestamp; it does not claim ongoing broker synchronization or unlock BUY eligibility on its own. Fresh marks, active stops, portfolio caps and the transactional entry/risk integration remain separate gates. Outside exposure cannot be silently omitted to obtain a match.

Authenticated GET/POST /api/v1/portfolio/reconciliation exposes the latest result and 20 recent statements. POST requires CSRF and Idempotency-Key. Owner-row locking serializes comparisons with journal writes. A retried identical request returns its original result; changed payloads and statements older than the latest source timestamp conflict. GET /api/v1/portfolio includes current reconciliation status and reasons. Original comparisons remain immutable after new statements or fills.

Run the root README migration/build/start steps; no broker credentials or external messaging are required for manual statement reconciliation. For tests, use `node scripts/database-command.mjs test reconciliation database` and `node --test tests/reconciliation.test.mjs`. Verification includes exact decimal discrepancies, outside holdings/references, future and old statements, concurrent journal writes, immutable history, authentication/CSRF and browser retry/mobile behavior. Synthetic financial fixtures remain confined to vcp_test and browser mocks.
