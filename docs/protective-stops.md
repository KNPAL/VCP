# Initial protective stops (KAN-97)

Migration 34 adds immutable initial position stops and protective SELL observations. An actual BUY journal transaction freezes the confirmed last contraction low minus one exchange tick, rounded down to the tradable tick. Its source must have been decided before the actual BUY. The stop and journal commit together. Missing verified mapping/structure yields an explicit UNKNOWN stop and never rejects or fabricates an actual fill.

The first BUY identifies a holding episode. Partial sells and top-ups retain its initial stop; closing the holding and buying again starts a new episode. Corrections retain historical stop evidence and block evaluation when the original fill evidence no longer matches. Initial stops are not automatically rewritten from a later pattern. EMA trailing revisions are separate work under KAN-98.

The worker evaluates held positions before screening work. A quote must pass mapped listing/session/source freshness and carry the Redis read's remaining validity window, bounded by heartbeat age, owner-lease expiry, quote TTL and session close. It rechecks validity after acquiring the portfolio lock. Quotes before the stop became effective cannot trigger it. Current verified corporate-action coverage must reproduce the frozen price basis; missing coverage, split/bonus basis changes or unverified actions block evaluation.

A fresh observed price at or below the stop emits SELL_PROTECTIVE once per stop/holding episode/exchange session. The exact observed gap price, quote time, recognition time, quantity at detection, quality and source stop are retained. Signal and deduplicated urgent SELL outbox entry commit atomically. No order is placed, no fill assumed, and no quantity changes. Only actual recorded fills change holdings.

Authenticated GET /api/v1/positions/stops returns current holding episodes, immutable stop history and the latest 100 protective observations. **My positions → Protective stops and observations** shows prices and timestamps, distinguishes unavailable price-scale evidence, and warns when current API evidence cannot be refreshed. A historical observation is not a pending broker order or proof of execution.

Use the root README migration/build/start steps. Genuine verified instrument, structure, action-coverage and live-stream inputs are required for live evaluation; no synthetic fixtures are inserted into the application database. Existing historical fills without valid pre-BUY context remain UNKNOWN. Tests use vcp_test, isolated Redis keys and browser fixtures, including exact tick rounding, gap price, quote/lease expiry, partial sells, new holding episodes, concurrent duplicate triggers, immutable evidence, price-scale changes and unchanged holdings after alerts.
